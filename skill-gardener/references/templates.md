# grow-skill 结构模板集

> 创建 controller 时复制对应骨架，替换 `<领域>`、`<hub>`（安装目录，Step 0 初始化配置）、`<runtime>`（当前引擎 skill 目录）和示例内容。

## 模板 A：controller SKILL.md 骨架

```markdown
---
name: <领域>-controller
description: <领域>自动化总控路由。当任务涉及<该领域的高频任务词>时，必须先加载本 skill 完成工具选型，任务后把新经验沉淀到本 skill 的 references/experience.md。触发词：<用户会说的词，5~10个>。
---

# <领域>-controller —— <领域>总控

<领域>任务的唯一入口：按路由表选工具 → 读对应 skill 文档 → 执行 → 沉淀经验。
skill 本体存放：`<hub>`（纯安装目录；生成 controller 时替换为实际路径）；
经验沉淀：本 skill 的 `references/experience.md`（只增不覆盖）。

> ⚠️ hub 与 runtime 的实际路径记在 `<hub>/CONFIG.md`（skill-gardener 初始化时写入）；路径变动时先更新它。

## 一、场景路由表

| 场景 | 工具 | skill 文档（读它拿完整用法） |
|------|------|------------------------------|
| <用户任务场景1> | <工具1> | <hub>/<skill1>/SKILL.md |
| <用户任务场景2> | <工具2> | <runtime>/<skill2>/ |
| ... | ... | ... |

**捷径**（高频组合直接给答案）：
- <场景> → <一句话方案>

## 二、命令速查

​```bash
# <工具1>（版本）——<定位>
<最高频的 5~8 条命令>

# 现成范式（已验证实现，优先参考改写）
<本领域已验证的脚本路径>
​```

## 三、动手前必读

先读 `references/experience.md` 的对应章节（<工具1>坑 / <工具2>坑），已知坑：
- <工具1>：<坑的一句话版>
- <工具2>：<坑的一句话版>

## 四、任务后沉淀（必做）

1. 新坑/新认知 → 追加到 `references/experience.md`（日期/场景/验证证据，只增不覆盖）
2. 完整案例 → 新建 `references/cases/<站点或场景>-capture.md`
3. 路由表有变 → 更新本文件 + `<hub>/INDEX.md`

## 五、工具版本与状态

| 工具 | 版本 | 状态 |
|------|------|------|
| <工具1> | <版本> | <首选/备选/弃用中> |
```

## 模板 B：experience.md 骨架

```markdown
# <领域>经验沉淀（追加式日志）

> **规范**：只追加不覆盖；每条必须带 `日期 / 场景 / 验证证据`；错误认知写「实测修正」保留轨迹。

## 目录

- [YYYY-MM / <主题>](#锚点)
- [<工具1> 通用坑](#工具1-通用坑)
- ...

---

## YYYY-MM / <主题>（完整任务经验）

**场景**：<什么任务>
**产物**：<脚本/文档路径>
**完整案例**：[cases/xxx-capture.md](cases/xxx-capture.md)

**方法链（已验证顺序）**：
1. <步骤>
2. <步骤>

**关键结论**：<本次沉淀的最重要认知>

## <工具1> 通用坑

| 日期 | 坑 | 绕法 | 版本 |
|------|-----|------|------|
| YYYY-MM-DD | <现象> | <绕法> | <外部工具版本> |

> 时效规则（借鉴 OKF 可信度机制）：坑表带版本锚定——外部 skill 官方升级后，逐条复核受影响条目：
> 仍成立的更新版本列；已被新版本修正的标记「已失效（vX.Y 已修复）」但不删除，保留轨迹。
```

2. ...

| 坑 | 原因 | 绕法 |
|----|------|------|

<可迁移到其他站点/场景的知识>
```

## 模板 D：hub INDEX 归属条目（聚合型收编时追加）

```markdown
| `<skill名>/` | runtime 目录下的 `<领域>-controller`（路径见 hub CONFIG.md） | 已移出运行时，由 controller 按场景引用 |
```

## 模板 E：hub CONFIG.md 骨架（Step 0 初始化时创建于 hub 根）

```markdown
# grow-skill 配置

- hub（skill 本体安装目录）：<实际绝对路径>
- runtime（当前 Agent 引擎的 skill 目录）：<实际路径，如 ~/.codebuddy/skills/>

> 用途：新建 controller 时替换模板中的 `<hub>` / `<runtime>` 占位符；查 skill 本体时定位 hub。
> 路径变动时更新本文件。
```
